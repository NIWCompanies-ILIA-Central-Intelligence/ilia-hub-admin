C · Where Logs Live — Two Layers
The design of the logs is separate from where they run — a wiki can't do real-time concurrent writes, so runtime logs live in the app database.
Design / working layerMarkdown-in-git (canonical) → Confluence mirror for humans. Lane working logs, specs, seat charters, prompts, skills. Git history = the immutable audit.
Runtime / operational layerApp database — Cloudflare D1 / KV. Per-user logs, per-lane logs, the event stream, conflict records, rule versions.
Reconciliation & log hygiene
Daily reconciliation + two-tier logsA daily sweep rolls events → summaries, cross-checks external systems, and diffs edits to the same object → flags conflicts. Each log = an AI-pruned hot summary over a never-deleted audit trail.
▼
