One pattern, every role — the capability ladder

CIH doesn't build a different tool per department. Every role climbs the same four rungs and reaches a different height depending on the job.

01

Know

Answers from the role's processes, docs, and source-of-truth.

"How does the DBR workflow route a notice?"
02

Diagnose

Pulls signal across systems and explains what's happening.

"Agent John can't log in — what's going on?"
03

Draft

Produces an artifact for review — a ticket, doc, prototype, or message.

"Draft an agent-onboarding training doc."
04

Act

Executes into a live system and records what it did — tiered, with owner green-light on compliance-sensitive actions.

"Create the JIRA ticket with acceptance criteria."

Built with governance & safety first

Because CIH can act on live systems, it's designed conservatively. These rules hold in every session and outrank any request.

Deny by defaultCIH does only what a role is explicitly granted. If unsure, it stops and asks.
Production gateLive-data & production gateNo live ILIA client data or production code until both are true: the owner's recorded approval and safeguards in place (restricted membership, read-only minimum-scope credential in a connector, audit log, minimum-disclosure).
New in v1.2Secrets never in chat or filesCredentials authenticate only — they live inside connectors or the project Instructions, never pasted into a chat or committed to a file. GitHub now authenticates through its connector, so no token ever touches a transcript.
Code-promotion gateLocal is free; promotion is gatedAnyone can experiment freely in their own local/sandbox environment. Nothing reaches shared / dev / live repos without explicit owner approval or a defined promotion workflow.
AuditServer-side audit log with PII maskingSensitive-access events are logged as structured records at a server chokepoint, with masking/redaction applied before any write — the log never receives raw PII. Default-deny when unsure.
AuthorizationPhase-1 membership-equivalenceLive ILIA data is permitted only while project membership is limited to NIW staff who already hold ILIA admin (all-client) access — CIH surfaces nothing beyond their existing entitlement. Add anyone narrower and live access pauses until the portal.
Review before actingDrafts, tickets, comms, and pushes are reviewed by a human before they go out.
Map, not territory · minimum disclosureOne source of truth, never a drifting duplicate. When handling client data, surface only the specific item asked for and never persist it to memory, files, or repos.
