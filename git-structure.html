CIH working repo — the Markdown-in-git master index
One company-owned Git repo is the canonical home for everything CIH authors: Core, every lane's working log, the portal spec, and the skills/tools. It's plain text — cheap to read, diffable, and its history is the immutable audit. Runtime user data and shared documents live elsewhere (called out below). This is the proposed layout (owner decision pending on making it canonical over Confluence).

Lives in git vs elsewhere

In git (this repo): Core, lane logs, portal spec, skills/tools, reference text. Text only.
NOT in git: runtime user/lane data → Cloudflare D1/KV · documents & assets (marketing, disclosures, carrier apps) → company Google Shared Drives · secrets/tokens → never in git · client PII → §10-gated.

How this powers the CIH portal

When the portal builds a user's session it reads core.md (rules) + portal/seat-charters.md (that seat's scope) to decide which tools from skills/ to mount and what the user may see/do. Each lane's working-log.md is the shared memory that keeps lanes in sync; the daily reconciliation sweeps them. Because it's Git, every change is diffable and versioned — the audit trail is free, and the Dev lane builds the live app straight from portal/.
